# 接管、TUN 与出口锁定

接管就是让流量进到 bowel 里。桌面版有两种方式，在首页的接管卡片里开关（「使用系统代理」「使用 TUN」），命令行是 `bowel on` 和 `bowel tun on`。Android 上的接管就是系统 VPN。

## 系统代理还是 TUN

- **系统代理**：bowel 把系统的代理设置指向自己。浏览器和大多数应用都跟随它；命令行工具、SDK、Docker 和不少游戏不跟随。
- **TUN**：一块虚拟网卡，接住那些不读系统代理的程序的流量。开着系统代理还有东西直连时，就用它。

在 macOS 和 Linux 上，「开发工具」还能逐个设置 Docker、终端和 Git：bowel 列出哪些没有接入，点一下写好它们自己的配置，撤销时原样删除。

### TUN 要什么授权

第一次开启 TUN 时需要管理员授权一次：macOS 是系统自己的对话框，Windows 是用户账户控制（UAC），Linux 通过 polkit（`pkexec`）。

在使用 systemd-resolved 的 Linux 上，这次授权还会留下一条 polkit 规则，允许当前用户把解析器指向 TUN 网卡（内核每次启动 TUN 都要这么做）。没有这条规则时（polkit 早于 0.106，不读取这类规则），每次启动 TUN 桌面都会连问三次密码。

### Linux

Linux 上的系统代理是 GNOME 的（Cinnamon、MATE、Budgie 等桌面共用它）或 KDE 的。其他桌面请使用 TUN，或让应用自行连接混合端口，默认是 7899。

## 出口锁定

有些流量一刻也不该从你自己的地址出去，比如不对你所在地区提供服务的 AI。在路由组的页面上锁定它的出口，它的流量就只走节点；走不了时，连接会断开，不会改走本机网络：

- **关闭接管时**：其他流量照常直连，只有锁定的路由组被拦下。为此系统代理会留着指向 bowel。
- **节点全部连不上时**：这个路由组被拦下，不改走直连。路由组里会写明，并给出出路：换一个能用的节点，或者解除锁定。
- **在全局或直连模式下**：锁定的路由组仍走自己的节点。

退出 bowel 后不再拦截。

命令行：

```bash
bowel route lock ai
```

### 出口锁定管得住什么

没开 TUN 时，出口锁定只管得住跟随系统代理的程序；不读系统代理的命令行工具、SDK 和应用仍会直连。要全部管住，请开着 TUN。

只开了 TUN 而 TUN 没有生效时，系统代理会临时指向 bowel 来守住它。如果系统代理也没能指向 bowel，锁会变红，写着「现在没有守住」，并说明怎么办。

Docker 镜像里没有系统代理。在那里，不管接管是开还是关，锁定都管住从 bowel 的端口和 TUN 进来的流量，其他流量也不会因此改成直连。锁定路由组的端口会管住所有使用它的流量，见[给其他容器当出口](../docker.zh-CN.md#给其他容器当出口)。

Android 上的开关同样在路由组的页面上。VPN 关着时手机拦不下任何连接，所以第一次锁定时会提示在系统设置的 VPN 里为 bowel 打开「始终开启的 VPN」和「屏蔽未使用 VPN 的连接」。那会在 VPN 断开时拦下手机上的全部流量，不只是锁定的路由组。

在 macOS 和 Linux 上，一台电脑还可以替局域网里的电视、游戏机和手机接管：见[网关模式](../gateway.md)（英文）。
